# TapLog V1 Implementation Roadmap

**Status:** Roadmap only — not a detailed implementation plan or `tasks.md`

**Sources:** [PRD](../../docs/product/TapLog_V1_PRD.md), [constitution](../../.specify/memory/constitution.md), and the approved [technical architecture](plan.md) and its contracts.
**Scope rule:** Each slice is a separately specified, implemented, and verified feature increment. No slice authorizes implementation of later slices or Future Scope.

## Dependency order

The requested decomposition is retained with two architectural ordering adjustments:

1. Duration and State semantics move ahead of rapid-action UI and external input channels, because every channel must invoke the same complete Event Engine rules.
2. Entitlement moves ahead of NFC Action Button completion, because the five-active-button limit must be enforced in the binding transaction, not added later as UI-only behavior.

## Slice handoff rules

- A slice begins only after its own Spec Kit feature specification, plan, and task list are approved; this roadmap does not replace those artifacts.
- Every slice verifies domain/application behavior test-first and runs proportionate Android/device checks before completion.
- Shared Event Engine and transaction contracts are extended only when a slice’s approved specification requires it; channels adapt commands and feedback, never redefine domain semantics.
- Advanced Pro statistics, dashboards, filtering, personalization, CSV/PDF export, and future integrations remain outside this roadmap until separately specified, as required by PRD §44.1.
